Run from the frontend directory:

```sh
node test/browser/smoke.mjs
```

Requires installed dependencies, Node 22.6+, the Firebase CLI, and a recent Google Chrome with MP4 MediaRecorder support. On macOS the default Chrome path is used. Elsewhere set `CHROME_PATH` to the Chrome executable. Ports 5188, 9198, 9248, 4458 and 4558 must be free.

The script starts its own local Firebase Auth emulator, development server and isolated headless browser, then stops them in `finally`. Logs, screenshots and the request list are saved in the temporary directory printed at completion. Browser downloads are explicitly restricted to that directory’s `downloads/` folder before navigation; the suite verifies the fixture there. It does not use your Downloads folder. It uses a demo Firebase project and deterministic API fixtures. Smoke mode ignores local environment files, clears Picker configuration (motion/projects checks use inert local fixture values; projects uses a local SDK fixture) and disables the Vite backend proxy; unfulfilled API/health requests return a fixture-required error. Chrome starts behind a deny-only proxy with exact bypasses for the local Vite and Auth emulator ports, including popups. The proxy never forwards HTTP, TLS tunnels or WebSockets; local canaries verify these boundaries and save `network-isolation.json`. This contains browser test traffic, rather than providing an operating-system sandbox. It never calls Google Drive, Anthropic, Deepgram or a production Firebase project.

Checks include isolated browser downloads, failed/malformed/ten-second stalled Drive status with source-local recovery, and the existing Drive flow and a YouTube-only flow with Drive unavailable, keyboard source selection, denied direct YouTube imports, import identity preserved across lost replies and reloads, all six YouTube output choices/results, import and generation retries using the same request key, all six output choices, partial results, authenticated text/image/video files, real browser MP4 metadata, revoked preview URLs, usage error recovery and expiry, disconnect failure, keyboard skip link, preserved navigation shell and sign-in across live/mobile/preview routes and browser history, reduced motion and screenshots at 375/768/1440 pixels. The 200% layout check uses half-width viewport with double pixel density; it does not automate the browser's zoom menu. Clipboard behavior is a fixture; no system clipboard is modified.

Screenshots support visual review. This small smoke suite does not replace a full accessibility audit or real-provider testing.

Submission regressions also check that a clear first quota rejection allows a new request, while lost or malformed responses retain the original key and payload through later rejections and reloads. Existing-generation conflicts reconcile with saved results. Failed or malformed allowance checks keep saved content visible and recover through the allowance retry.

For the focused motion checks, run `RIFLO_SMOKE_MOTION_ONLY=1 node test/browser/smoke.mjs`. It reuses local cold/cached account fixtures, then records native route/content animation timings and intermediate opacity/transform frames, theme snapshot progress, rapid navigation/appearance choices, system/prepaint behavior and reduced-motion cancellation in `motion-checks.json`, with before/during/after theme and output screenshots in the printed artifact directory. `project-motion-checks.json` additionally records cold/cached ledger geometry and intermediate import disclosure heights, rapid reversal, inline invalid-link feedback, draft recovery, dynamic reduced motion and responsive Picker geometry at 375/600/601/1440px in both themes. The detail suite records primary source states and compact source completion; the generation-default suite records six-row loading geometry at these same widths.

Generation checks use six direct per-format actions, each creating one output. Native keyboard activation and exact singleton request assertions cover paid intent and uncertain-response replay. Focus and held-response checks compare exact row/action geometry through ready, sending, active and completed states at 375/1440 pixels in both themes. Rapid sibling clicks admit one request, repeat generation appends identifiable results without replacing the reader, and saved content remains usable when generation progress cannot load. Saved requests created with multiple outputs retain their original counts and request identity through recovery.

For the communication checks, run `RIFLO_SMOKE_COMMUNICATION_ONLY=1 node test/browser/smoke.mjs`. Command and operation observation fixtures use actual local HTTP `text/event-stream` responses, delivered in delayed byte chunks through the application's Fetch/SSE parser. The extra fixture port is allocated dynamically and added as an exact deny-proxy bypass; it never forwards traffic. Canonical project, generation and output reads remain JSON fixtures. `communication-checks.json` records the checks, request list, transport closure/chunk evidence, screenshots and SHA-256 source/artifact hashes. Hidden/visible events are driven through a test-only document visibility override so lifecycle cleanup is deterministic in headless Chrome. Local checks do not establish production proxy flushing or worker execution.

For focused direct-import transport checks, run `RIFLO_SMOKE_IMPORT_COMMUNICATION_ONLY=1 node test/browser/smoke.mjs`. This runs the import section of the communication fixture: one direct POST receives real HTTP SSE acceptance, navigates before terminal completion, clears its saved intent, and recovers a lost response through reload and a superseded accepted response with the original key and payload.
